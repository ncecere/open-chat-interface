## Branding applied everywhere

Branding (Admin > Branding) sets the app name, a short name, a logo (uploaded
or linked), a colour theme, the default light/dark theme and a sign-in
message. This item audits every surface that shows the instance's identity,
fixes the ones that ignored it, and puts the Open Chat Interface mark
("Turns") into the app as the default.

### Decisions

**Diagram accent.** `DIAGRAM_ACCENTS` in `@oci/shared` maps each colour theme
to its **light-mode** `--accent` from `tokens.css`, because diagrams are drawn
on light paper (`#f5f5f5`) whatever the app's theme: blue `#155dfc`, violet
`#7f22fe`, emerald `#007a55` (4.8:1 or better on the paper). Neutral's accent is
near-black (light) or near-white (dark); either would vanish against the ink
`#2d3142` or the paper, so neutral keeps Diagram Design's orange `#eb6c36`,
which is also every existing default instance's current colour (no change for
them). A web unit test converts the OKLCH tokens and fails if they drift from
the map.

**`accentColor`.** Kept as an **API-only override** for diagrams: a valid hex
set with `PATCH /api/admin/settings` wins over the theme; `null` returns to the
theme. The update schema now rejects anything but `#rgb[a]`/`#rrggbb[aa]`, so a
typo is a 400 rather than a silently ignored value. Removing it would have
dropped a working API field that an instance with a house colour may use.

**Favicon from the upload.** The uploaded logo is served same-origin at
`/api/branding/logo` (PNG/JPEG/WebP, cache-busted by key), so the client
points the `<link data-brand-icon>` elements (icon ×2, apple-touch-icon) at it
and drops their `type`/`sizes`, which describe the defaults. No server-side
scaling: browsers scale icons, and the upload is at most 1 MB. A linked
external logo keeps the Turns icon, so tabs do not fetch a third-party image.

**The default mark.** `TurnsMark` inlines `mark-small.svg` (the 20–47 px
drawing) from oci-assets `logo/turns` at commit 9ce4afe; the favicons are
copied unchanged. The tile mark reads on light and dark (logo README), is never
recoloured to the accent theme, and is `aria-hidden` beside the live-text name.
When a logo is uploaded it replaces mark and name as before.

**Page titles from the path.** `pageTitleFor` names pages without touching
the router: admin pages come from `NAV_SECTIONS`, so new admin pages are named
for free; a page with a better name (a shared conversation) calls
`usePageTitle`. `DocumentBranding` is mounted beside `RouterProvider` and reads
the router's location through `useRouterState({ router })`.

### Shared components touched (kept minimal)

- `components/layout/sidebar.tsx`: the header's link/wordmark and the right
  spacer only.
- `routes/share/public-share.tsx`: the header wordmark and a `usePageTitle` call.
- `services/documents/*` (render, worker, model, four generators): one
  `creator` field threaded through; no layout change.
- `services/export.ts`: an optional `source` argument to `renderMarkdown`.

### Tests

- Web unit: `branding.test.tsx` (wordmark default/compact/logo, title per
  route, favicon swap and restore, `usePageTitle`, share header, diagram
  accents vs `tokens.css`).
- API unit: `branding.unit.test.ts` (accent mapping and override, update schema,
  From header, app-name fallback, document creator metadata).
- API live: `smtp-email.live.test.ts` (subjects, bodies and sender name on the
  wire via Mailpit), `artifacts.live.test.ts` (system prompt follows the
  theme, override wins), `thread-export.live.test.ts` (Markdown header).
- E2E: `branding.spec.ts` sets name, colour theme and an uploaded logo through
  the admin API and checks the tab title, tab icon, sidebar header, sign-in
  page and a public share page, then restores the original branding.
